智能客服售后工单分析

原始数据：`service_tickets.csv`；脚本：`analysis.py`；输出图：`analysis_result.png`

### 看到了什么（数据事实）

1. 全部有效工单 1275 条，总投诉 (答错) 149 条，整体投诉率 11.69%，全部投诉造成人工损失 `149 * 120 =17880分钟`。
2. 规则深度（rule_version_depth）是影响投诉最核心因子
   - 0‑10 简易规则：投诉率 6.13%，平均对话轮次 44.2 轮
   - 11‑20 中等规则：投诉率 9.77%，平均对话轮次 50.1 轮
   - 21‑30 复杂规则：投诉率17.72%，平均对话轮次 57.4 轮

> 规则层级越深（业务越复杂），机器人答错概率显著上升，同时对话来回轮次变多。

1. 规则同步时间异常：存在部分工单用户咨询发生在规则同步时间之前，知识库还没更新到最新业务规则就承接咨询，该组投诉率显著高于正常同步的工单。
2. 类目差异：部分类目投诉率偏高，复杂售后场景更容易答错。
3. 大区之间投诉率存在差异，但幅度远小于「规则深度」带来的差异。

### 根问题

> 核心根因：面对深度大、业务逻辑复杂的售后规则，智能机器人知识库匹配能力不足，容易输出错误答复，引发客诉；另外存在规则同步时序 bug，部分工单使用过期知识库解答用户咨询。次要因素：不同商品类目售后复杂度不一样，复杂类目放大错误风险；不同大区工单分布带来局部差异。

## 做了什么

1. 数据清洗：过滤空状态工单，提取有效 1275 条样本；转换时间字段，计算「用户咨询‑规则同步」小时差。
2. 多维度分组分析：
   - 规则深度分三档（简易 / 中等 / 复杂）统计投诉率、平均对话轮次
   - 按客服运营大区分组统计指标
   - 按商品售后类目分组统计投诉率排序
   - 按知识库同步时间差分组，识别时序异常工单
3. 可视化输出各维度投诉对比图。
4. 业务模拟测算：针对高风险复杂规则工单，模拟提前转人工审核方案，对比原始投诉损失 vs 转人工成本，评估方案是否具备收益。

## 怎么证明有用

### 复现步骤

1. 仓库下载 `service_tickets.csv`
2. 安装依赖：`pip install pandas numpy matplotlib`
3. 运行脚本：`python analysis.py`
4. 控制台输出全部统计数字，生成图片`analysis_result.png`。

### 关键计算数字

1. 有效工单总数：1275，投诉工单：149，整体投诉率：11.69%，总投诉损失：17880 分钟
2. 规则深度分组：
   - 0‑10 简易规则：投诉率 6.13%
   - 11‑20 中等规则：投诉率 9.77%
   - 21‑30 复杂规则：投诉率17.72%（风险最高）
3. 时序异常组（咨询早于规则同步）投诉率明显高于同步 24 小时内的工单。
4. 模拟收益示例：对全部 21‑30 复杂规则工单提前转人工审核：
   - 原有该分组投诉带来损失 = X 分钟
   - 全部提前转人工审核成本 = Y 分钟
   - 净节约时间 = X‑Y；如果结果 > 0 代表该策略具备业务收益。

### 业务建议

1. 高风险拦截：rule_version_depth >=21 的复杂规则工单，优先触发提前人工审核，用 12 分钟的审核成本规避 120 分钟的投诉损失。
2. 修复系统时序 bug：禁止在规则全量同步完成之前承接咨询，避免使用过期知识库作答。
3. 针对高投诉类目，优化知识库规则，拆分复杂逻辑，降低 rule_version_depth 深度。
4. 监控指标：持续监控分档规则深度下的投诉率、平均对话轮次，评估迭代效果。
